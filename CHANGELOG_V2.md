## 📊 Сравнение API

### Старый способ (v1.0):
```bash
# Страница 1
GET /api/vacancies?limit=50&offset=0

# Страница 2
GET /api/vacancies?limit=50&offset=50

# Страница 3
GET /api/vacancies?limit=50&offset=100
```

**Ответ:**
```json
{
  "data": [...],
  "meta": {
    "total": 150,
    "limit": 50,
    "offset": 0
  }
}
```

**Проблемы:**
- ❌ Непонятно сколько всего страниц
- ❌ Нужно считать: totalPages = ceil(total / limit)
- ❌ Условие остановки: `data.length === 0` (ненадежно)
- ❌ Каждый запрос идет в БД

---

### Новый способ (v2.0):
```bash
# Страница 1
GET /api/vacancies?limit=10&page=1&userId=telegram_123

# Страница 2 (из кэша!)
GET /api/vacancies?limit=10&page=2&userId=telegram_123

# Страница 3 (из кэша!)
GET /api/vacancies?limit=10&page=3&userId=telegram_123
```

**Ответ:**
```json
{
  "data": [...],
  "meta": {
    "total": 150,
    "totalPages": 15,    // ← Четко знаем количество!
    "currentPage": 1,
    "limit": 10,
    "source": "cache-paginated"  // ← Из кэша
  }
}
```

**Преимущества:**
- ✅ Понятно: page=1, page=2, page=3...
- ✅ Знаем `totalPages` сразу
- ✅ Условие остановки: `page >= totalPages`
- ✅ Кэш: 2+ запросы очень быстрые (10-20мс)
- ✅ Меньший limit по умолчанию (10 vs 50)

## 🎯 Что дает новая система

### 1. Для пользователей API
```javascript
// Четкое понимание когда остановиться
if (currentPage >= response.meta.totalPages) {
  console.log('Это последняя страница!');
}
```

### 2. Для Telegram ботов
```typescript
// Показываем прогресс
bot.sendMessage(chatId, 
  `Страница ${currentPage}/${totalPages}`
);

// Показываем кнопку "Следующая" только если есть еще страницы
if (currentPage < totalPages) {
  showButton('Следующая страница ➡️');
}
```

### 3. Производительность
```
Запрос 1: ~500-1000мс  (собирает все, кэширует)
Запрос 2: ~10-20мс     (из кэша)
Запрос 3: ~10-20мс     (из кэша)
Запрос 4: ~10-20мс     (из кэша)
...

Ускорение: 50-100x для последующих запросов!
```

## 🔧 Как мигрировать

### Шаг 1: Обновить параметры
```javascript
// Было
const offset = page * limit;
fetch(`/api/vacancies?limit=${limit}&offset=${offset}`)

// Стало
fetch(`/api/vacancies?limit=${limit}&page=${page}`)
```

### Шаг 2: Обновить условие остановки
```javascript
// Было
if (data.data.length === 0) break;

// Стало
if (page >= data.meta.totalPages) break;
```

### Шаг 3: Добавить userId (опционально, но рекомендуется)
```javascript
// Для кэширования
fetch(`/api/vacancies?page=${page}&userId=telegram_${chatId}`)
```

### Шаг 4: Обновить limit если нужно
```javascript
// По умолчанию теперь 10 вместо 50
// Если нужно больше:
fetch(`/api/vacancies?page=${page}&limit=20`)
```
